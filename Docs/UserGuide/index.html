01 · What CyGameCapture does

CyGameCapture selects images inside a game’s rendering pipeline and shares them through Spout2. You can keep the normal game image with its interface while sending a clean scene to OBS, capture depth, isolate the HUD or send several buffers at once.

  • ReShade add-on: inspect a running game, choose a render target and publish it.
  • OBS plugin: receive a stream as a source and optionally record several sources into separate files.
  • Unreal plugin: send render targets, scene captures or a viewport, and receive Spout images inside Unreal.
  • AI helper: propose a buffer and a capture moment from images of a D3D11 frame.

Sharing and the normal capture path stay on the GPU. Encoding a recording is a separate operation; the AI helper reads small images in its own process when you request an analysis.

The screenshots use a small animated test scene so each function is easy to identify. They are actual application captures, not mock-ups.

02 · Install and update

Requirements

Use Windows 10/11, a 64-bit game and a supported DirectX renderer. D3D11 and D3D12 are the tested capture backends; D3D10 support is limited. Moment capture and AI analysis currently require D3D11. Vulkan and OpenGL are not supported by this capture pipeline. Use a game in which ReShade is allowed and works normally.

ReShade

  1. Install ReShade 6.8.0 with add-on support for the game and its actual graphics API. A plain ReShade build cannot load this add-on; the target API is 20.
  2. Extract the ReShade archive. Copy CyGameCaptureRS.addon64, CyGameCaptureAI.exe, Documentation and the licence files together next to the game executable, or into the configured ReShade add-on directory.
  3. Start the game. Open ReShade with Home. Find CyGameCaptureRS – Buffer Inspector. Its header includes a User guide button.

OBS

Use 64-bit OBS Studio 29.1 or later (tested against 29.1.3). Close OBS. Extract the entire OBS archive and run Install-OBS-Plugin.cmd, or use the test suite’s installer. Start OBS and add a CyGameCapture source. A generic Spout2 receiver is another option. The native plugin’s source properties include User guide; the manual is installed with its data.

Update or remove

Close the game and OBS before replacing loaded binaries. Keep an older package for rollback. Replace binaries, helper, documentation and notices together. Preserve ReShade.ini, OBS settings and scene collections. Do not replace your game’s configuration with the test application’s demo INI. To remove the add-on, remove its files from its installation directory; use the supplied OBS uninstaller for the OBS component. Unreal installation is described in chapter 12.

03 · Your first clean capture

  1. Reach actual gameplay with a visible HUD. Avoid a black loading screen.
  2. Open the overlay with Home, then Buffer Inspector.
  3. Choose a complete, correctly coloured image without the HUD in the contact sheet. Inspect it in the preview. If none exists, try a moment before the HUD or the AI assistant.
  4. Click Use As Capture Source. In Capture, check the stream’s resolution, FPS, sent frames and output preview.
  5. In OBS, add CyGameCapture and select CyGameCaptureRS::<Game>. Use Refresh if necessary.
  6. Close the ReShade overlay. Keep your usual HUD in the game while OBS receives the selected scene.

04 · Find and inspect buffers

A buffer / render target is a texture used by the game while drawing a frame. The final display image is the back buffer. Many other targets contain intermediate data such as normals, lighting or depth: an image resembling the scene is not necessarily ready to display.

The Contact Sheet shows thumbnail previews. Click one to select it. The table lists its ID, size, format, writes and Steady percentage. A good persistent source is written almost every frame. Steady buffers only hides temporary resources; disable it when investigating a missing target.

  • Use filters for recently written textures, colour, depth, MSAA, mip/array resources, size relative to the back buffer and format. Change sorting if necessary.
  • Use Previous / Next, the arrow keys or a row click to browse. Freeze Preview freezes inspection; it does not pause the game.
  • Check the full image: no missing objects, HUD, blur, unexplained colours or stale borders. Prefer the final tonemapped colour for normal SDR capture.
  • Dynamic resolution can render into only part of a full-sized texture. The overlay reports the active rendered area and the capture scales it to a stable stream size.
  • Buffer IDs are stable only within a run. Recheck them after restarting the game or changing graphics settings.

Timeline and Debug

Timeline lists clear, draw, copy, resolve and present events in the last frame. Filter to writes or the selected resource; clicking an event selects its resource. Debug shows backend, frame index and tracker counts. Enable verbose tracking only while investigating: logging every resource can produce large logs.

05 · Capture before the HUD is drawn

Some games draw the finished scene and the interface into the same back buffer. At the end of the frame there is no clean target left. Select the back buffer and capture it between those writes.

  1. Select the back buffer in the inspector.
  2. Read Writes of this buffer in the last frame.
  3. Move Moment of the frame back from the end until the preview shows the complete scene without the interface. A clear-only or partial image means you went too early.
  4. Use this setting as the capture source. The preview, capture and in-game view use the selected moment.

Example: in Stray’s tested menu, #005 after write 2 is after the tonemapper and before the interface. This is an example, not a universal setting: the ID and order depend on the game and scene. A logo drawn as part of the 3D scene remains.

D3D11 only. Multisampled targets cannot currently be captured at an intermediate moment. Each moment in use adds a full-sized GPU copy per frame. D3D12 writes are recorded in parallel, so this ordering feature is unavailable there.

06 · Play with the selected image

Enable Show selected buffer in game or press F10 to replace the image displayed to the player with the selected buffer. Toggle again to restore the normal view. The shortcut can be changed with ViewToggleKey; zero disables it.

This is separate from sending a stream: a correct in-game image does not prove that capture has been started or that OBS has selected the right sender. Confirm the output in the Capture tab.

The selected texture must match the back buffer’s size and have a copy-compatible format. Scaling and format conversion for this particular in-game replacement are not available. Use the clean scene or a moment capture when compatible; depth and HDR intermediates may not be suitable to display directly.

07 · Streams, previews and alpha

Use As Capture Source selects the main stream. Add As Extra Stream publishes another buffer without replacing it. Sender names use CyGameCaptureRS::Game, then ::2, ::3, etc. Use each stream’s Stop button when it is no longer needed.

The Capture tab reports active status, sender, source, resolution, format, FPS, sent/skipped frames and CPU copy cost. Output preview (what OBS receives) displays the published texture. The inspector preview only proves what is selected, not what an existing stream is sending.

Transparent image even though RGB is correct

Some games leave alpha at zero in a complete colour image. Colour streams are opaque by default; RGB is unchanged. Enable Preserve source alpha (advanced) only when you actually need the source transparency. This is per stream; PreserveSourceAlpha sets the default for new streams. HUD-derived streams always preserve their mask. The inspector preview displays RGB opaquely, so it can look fine even when a receiver blends a preserved zero-alpha texture away.

Flush after copy submits D3D11 work immediately. Leave it off normally; try it when diagnosing delivery latency. It is not a repair for a wrong source or missing receiver and adds CPU work.

08 · Receive and compose in OBS

  1. Start the game’s capture first.
  2. In OBS, Sources → + → CyGameCapture. Name the source by purpose, such as Clean, HUD or Depth.
  3. Choose the exact sender. Refresh the list re-reads discovery. Enable List every Spout sender to include non-CyGameCapture applications.
  4. Check status, resolution and FPS. Fit the source to the canvas and ensure it is visible in the current scene.

Automatic selects an available CyGameCapture sender; choose an explicit name for predictable multi-stream setups. Reconnect automatically reconnects when the selected sender returns. Hold the last frame retains the last picture during a missed transfer; it can look like a freeze while the producer is stopped. A previously selected sender may remain listed as not running.

Spout sharing is local to this PC. Use the same GPU for the game and OBS, especially on laptops with integrated and dedicated graphics. A visible sender name proves registration, not a healthy image. Use the output preview and the diagnostic receiver to isolate the problem.

For composition, put an isolated HUD source above the clean source. Transparent pixels require an alpha-preserving stream and a compatible recording mode if saving that layer. Separate sources can be different sizes: check their transforms.

09 · Record several buffers together

The native OBS plugin can record several buffers into separate synchronised files, independently of an ordinary recording of the OBS canvas.

  1. Create one CyGameCapture OBS source per buffer and choose explicit senders.
  2. Enable Record this buffer on each source to include it in the take.
  3. Select the take folder, encoding, container and OBS audio track (1–6).
  4. Click Start recording all selected buffers once. Stop with Stop recording.
  5. Check each file and the status counters, skipped frames and reported drift. Files share a take time stamp and include their source/sender name.

Each source uses a video mix at its native resolution, encoder and muxer. Producers publish matching frame indices; the recorder reports differences when it can verify them. Frame synchronisation is measured, not a promise that no frame can ever be missed.

EncodingUseLimits
Hardware (NVENC / AMF / QuickSync; software fallback if selected)Normal colour video; smaller filesYUV conversion can lose colour precision, chroma and alpha. Not appropriate for preserving depth.
Lossless 8-bit RGB · FFV1Exact 8-bit colour and isolated HUD masksPreserves alpha; limited to 8 bits.
Lossless 16-bit 4:4:4 · FFV1Higher-precision depthYUV, no alpha. OBS internally uses half floats, so full 16-bit unorm precision is not retained.

Use Matroska (.mkv) for recoverable takes. An interrupted MP4 may be unusable. Lossless modes use FFV1 and the Matroska path; allow enough disk space and verify a short take first. An audio track is an OBS mix: configure its contents in OBS’s Advanced Audio Properties. Each file can receive the selected mix; this does not create game audio directly.

Start the take by itself begins when every selected source has a picture, once per OBS run. Disable it for manual control. See verification tools to inspect what a file really preserved.

10 · Ask the AI assistant

The assistant uses an installed, signed-in Claude Code, Codex or OpenCode client. It is optional; manual capture works without it. CyGameCapture does not include a model or store a provider API key.

  1. On D3D11, show real gameplay with the interface visible.
  2. Choose a client in AI Assistant and click the search button. A discussion window opens.
  3. The add-on samples buffers and moments into a shared GPU image. CyGameCaptureAI.exe reads the images outside the game and asks the selected client to identify a complete scene without HUD.
  4. Read the explanation and proposal. Show selects it for inspection; Apply uses it for capture; Apply, and send the interface alone too also requests a HUD-derived stream.
  5. Reply with details such as “subtitles remain”. Keep Attach the current frame on to send fresh images. Send with the button or Ctrl+Enter. New discussion clears the conversation.

The proposal includes a buffer ID and, where appropriate, a write moment. It is checked against the sampled frame. Inspect it: a scene change can invalidate the recommendation. Black loading screens, obscured gameplay or absent HUD give the model too little evidence.

Privacy and diagnosis

Your chosen client’s provider receives the sampled pictures, buffer metadata and conversation through your account. The last 12 messages can accompany the next request. Client activity may use your provider allowance. Review local files at %LOCALAPPDATA%\CyGameCapture\AI\<game>: prompt.txt, answer.txt and picture_NN.png. They can contain game images and conversation text. Delete them when no longer needed; redact them before sharing.

Optional settings: AIClient, AIModel, AIClientPath and AILanguage. If a client is missing, install/sign in to it separately, then select its executable path if automatic discovery fails. If the helper is absent, restore it next to the add-on. Analysis at frame moments is not available in D3D12.

11 · Depth and isolated HUD

Depth

Select a depth texture and click Use As Depth Stream. CyGameCapture linearises it into R16G16B16A16_UNORM. Adjust far plane, reversed Z, logarithmic depth and upside down for the game, as with ReShade’s depth settings. Incorrect parameters produce an inverted, almost white or geometrically wrong result. Select a main scene depth buffer, not a shadow map. Verify near/far changes as you move.

HUD on its own

  1. Capture the clean scene as stream 1, either from a separate target or an intermediate moment.
  2. Select the finished image at the end of the frame, usually the back buffer.
  3. Click Isolate HUD Against Stream 1.
  4. Adjust HudThreshold and HudSoftness to reject scene differences without erasing text. HudKeepFinalColour keeps the final interface colours.

The derived HUD is the difference between the final image and the clean scene with a transparency mask. Opaque HUD areas can be exact; soft edges and effects are approximations. Motion, differing post-processing or a wrong moment can leave scene artefacts. When the game already has a transparent HUD-only render target, capture it directly and preserve its alpha instead.

Both derived passes work on D3D11 and D3D12. Their availability does not make D3D12 intermediate-moment capture available. To record a HUD with transparency use lossless 8-bit RGB; the other recording paths drop alpha.

12 · Unreal Engine sender and receiver

Install the package matching your Unreal version into <Project>\Plugins\CyGameCaptureUE, enable the plugin and restart. Supplied prebuilt archives cover the engine versions named on those archives. The source targets UE 4.27–5.8; 4.27 compilation remains unverified. Win64 D3D11 and D3D12 are the supported RHIs. The offline manual is also at Docs/UserGuide/index.html in the plugin.

Send an image

  1. Add a CyGameCapture Spout Sender component to an actor.
  2. Choose Render Target (assign a UTextureRenderTarget2D), Scene Capture (use an existing component or leave empty to create one), or Game Viewport (no second scene render).
  3. Choose a stream name and keep Auto Start on. Begin Play publishes CyGameCaptureUE::Project::Stream.
  4. Select that sender in OBS or another Spout receiver.

Managed scene captures expose size/format settings and cost another scene render. Custom frame rate limits GPU copies. Supported targets include RGBA8, RGBA8 sRGB, RGB10A2, RGBA16f and RGBA32f. Other formats raise an error; HDR float images need a suitable receiver or conversion to SDR. Name collision policies are Fail, Auto Rename or Replace If Owned By This Process. Do not give multiple live streams the same fixed name.

Receive an image

  1. Add a CyGameCapture Spout Receiver component.
  2. Set the exact sender name; Get Available Spout Sender Names lists candidates.
  3. Keep Internal Render Target and Auto Connect on for a managed output. User Render Target mode needs your own target and optional automatic resizing.
  4. On On Connected, get Get Receiver Texture and assign it to a dynamic material’s texture parameter. For UMG, use a UI material on an Image brush.

Events report connection, disconnection, frame arrival, size, format and errors. Frame events can be throttled. Resize handling preserves the render target object but may recreate its underlying texture. Streams stop on EndPlay/world teardown.

Settings and diagnosis

Project Settings → Plugins → CyGameCapture controls defaults, editor capture and limits. PIE in the main editor viewport captures the whole editor window back buffer; use New Editor Window or Standalone for an isolated game view.

14 · Performance and compatibility

  • Normal streams require one GPU copy per frame; D3D12 uses a D3D11On12 bridge with additional work. Derived streams and moments add GPU passes/copies. CPU copy cost in the UI is not total GPU or encoder cost.
  • Resolution, number of streams, recording encoders and disk bandwidth affect throughput. Start with one stream and add others while checking FPS, skipped frames and GPU load.
  • There is no fixed product stream count. Spout’s machine-wide sender table has 64 entries by default, shared with other applications. Stop unused producers. Advanced users can change HKCU\Software\Leading Edge\Spout\MaxSenders through Spout’s settings. Receivers do not consume sender slots.
  • Safety limits such as the add-on’s 256-stream sanity limit and Unreal’s StreamSanityLimit protect against runaway creation. They are not a performance guarantee.
  • A float HDR/normal/lighting target is not an SDR display image. Pick the tonemapped scene or arrange conversion in the producing application. Format and resolution compatibility matter for every receiver.
  • Textures can disappear after a mode change. Refresh, reselect and test after resizing, changing graphics settings or switching scenes.

16 · Test and verify a recording

The test suite includes D3D11/D3D12 applications with a simple scene and fake HUD, plus a Spout receiver. It lets you separate an installation problem from a game-specific buffer problem.

CyGameCaptureSpoutReceiverTest.exe --list
CyGameCaptureSpoutReceiverTest.exe --frames 3 --out C:\Captures

Run with an existing writable output folder. The receiver lists CyGameCapture senders and writes received frames as BMP. If it receives the correct image, investigate the OBS source/format rather than buffer selection.

The optional VideoProbe decodes a saved file and reports codec, pixel format, component bit depth and distinct values:

CyGameCaptureVideoProbe.exe "take.mkv" 2
CyGameCaptureVideoProbe.exe "take.mkv" 2 --dump 3 "C:\Captures\Alpha"

Component indices depend on the decoded pixel format; component 3 is alpha only if that format actually contains alpha. The tool uses FFmpeg libraries installed with OBS. Absence of alpha in the decoded format means it was not saved, even if the incoming Spout texture had one.

In measured depth tests, hardware, lossless 8-bit and lossless 16-bit paths retained 214, 249 and 4945 distinct values respectively. These are test results, not universal guarantees. An encoder’s “16-bit” label alone does not demonstrate 16-bit source preservation.
